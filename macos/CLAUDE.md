# hellobhai for macOS - Agent Instructions

<!-- Mac app details. The repo-wide map and shared conventions are in ../CLAUDE.md. All paths and commands below are relative to macos/. -->

## Overview

Local-first macOS menu bar companion app. Lives entirely in the status bar (no dock icon, no main window). Push-to-talk (ctrl+option) captures voice, transcribes it on-device with Whisper (Hindi/English/Hinglish), and sends the transcript + screenshots to Claude via the local `claude -p` CLI. The reply is spoken with on-device neural TTS (Supertonic-3, one voice for English and Hindi) while a blue Dynamic-Island-style pill grows out of the notch. A small draggable orb (Rive animation) shows what bhai is doing; when Claude points, clicks or draws, a blue pointer launches out of the orb, does it, and flies back in. Clicking the orb opens a typed side chat that uses the same pipeline. Claude can click, type, and press keys for the user. The assistant is called "bhai" in all UI text; "hellobhai" is only the app name.

No servers, API keys, analytics, or auto-updater. Network traffic is `claude -p` itself plus one-time model downloads from Hugging Face on first launch (~1GB total).

## Architecture

- **App Type**: Menu bar-only (`LSUIElement=true`), no dock icon or main window. Not sandboxed (needed to spawn `claude`).
- **Framework**: SwiftUI (macOS native) with AppKit bridging for menu bar panel and cursor overlay
- **Pattern**: MVVM with `@StateObject` / `@Published` state management
- **AI Chat**: `claude -p` subprocess (`ClaudeCLI.swift`). Model alias `fable`, `opus`, `sonnet` (default) or `haiku`. Screenshots go in as base64 image blocks over `--input-format stream-json`; text deltas come back over `--output-format stream-json --include-partial-messages`. Runs with `--strict-mcp-config --disable-slash-commands --setting-sources project --no-session-persistence` from the temp dir so no user/project context leaks in. Voice turns pass `allowsMacTools: true`: `--tools Bash,Read` with an `--allowedTools` allowlist (`osascript`, `open`, `mdfind`, `shortcuts`, `ls`, `Read`) and `--add-dir ~`; anything else non-read-only is denied in print mode. The onboarding demo runs with `--tools ""`. Each voice request is an agent loop of up to 8 screenshot → claude → actions rounds.
- **Speech-to-Text**: WhisperKit (`large-v3-v20240930_626MB`) with auto language detection, batch-transcribed on hotkey release; clips detected as Urdu are re-transcribed as Hindi (they sound alike). The prompt tells Claude transcripts can mishear technical terms. Model stored in `~/Library/Application Support/hellobhai/Models`. Falls back to on-device Apple Speech (needs Dictation enabled) until the model is loaded.
- **Text-to-Speech**: FluidAudio, two engines picked in the panel (UserDefaults `selectedTTSEngine`, `selectedKokoroVoice`, `selectedSupertonicVoice`). Default is Supertonic-3 voice F2 for both languages (lightest and fastest; picked by ear). Optional Kokoro-82M (`KokoroAneManager`, `.english`, legacy runtime because v3 crashed on macOS 27, voice `af_heart`; model in `~/Library/Application Support/hellobhai/Models`, shared G2P files in `~/.cache/fluidaudio`), loaded lazily only while selected and warmed with one throwaway synth. Kokoro has no Hindi, so sentences containing Devanagari always go to Supertonic-3 (`Supertonic3Manager`, voice F2 by default, language `hi`); Supertonic is always loaded and also speaks English when selected, while Kokoro is loading, or when Kokoro throws on a sentence. Synthesized one sentence at a time with the next sentence prepared during playback (24 kHz Kokoro / 44.1 kHz Supertonic clips, one WAV each). Falls back to `AVSpeechSynthesizer` until models load or on failure. Claude is told to reply in natural Hinglish (Hindi grammar, everyday English words) written in Devanagari when the user speaks Hindi/Hinglish, so the voice reads it as Hindi.
- **Computer Control**: Claude appends `[CLICK:x,y:label:screenN]`, `[TYPE:text]`, `[KEY:cmd+s]` tags; `ComputerControl.swift` replays them as `CGEvent`s (Accessibility permission). The pointer flies out of the orb to each click target 1.2s before clicking; pressing the hotkey (in either hotkey mode, via `stopEverythingInProgressForHotkeyPress`) cancels remaining actions. Screenshots leave out every own-app window, so `performComputerActions` hands keyboard focus back from the chat (`giveKeyboardFocusBackToFrontmostApp`) and makes the chat panel and the orb click-through (`setLetsClicksPassThrough`) until the actions finish. Only on explicit user request (enforced by prompt).
- **Typed Chat**: `ChatPanel.swift` (`ChatPanelManager` + `ChatPanelView`): a 380pt dark card in a non-activating but key-capable `.floating` `NSPanel` that slides in from the right or left edge of the screen under the mouse (full visibleFrame height, 12pt inset; side in UserDefaults `chatPanelSide`, switched from the header swap button or the panel). Minimize (chevron button, Esc via `cancelOperation` and `.onExitCommand`, or the chat hotkey) shrinks it to a 30×112 tab flush with the edge that shows an unread dot once reply text arrives; minimizing hands the keyboard back to the user's app. The close animation is cancelled if the chat reopens mid-slide, and a disconnected screen falls back to the panel's current one. `CompanionManager.sendTypedChatMessage` runs the same screenshot → claude → agent-loop pipeline as voice (`sendTranscriptToClaudeWithScreenshot(isTypedChatMessage: true)`); every voice turn also lands in `chatMessages`. Replies stream into a placeholder row with only bhai's own tags hidden (`chatDisplayText`, known tag names only); each request finishes or removes only its own rows on cancel/error. Reply rules: spoken question → always spoken (also shown in chat); typed question → text, or text + voice when `speaksChatReplies` is on; circle-to-ask stays voice-only. While the chat is visible the orb drops to `.floating` and is ordered below it (`onChatWindowShownOrHidden` → `OrbWindowManager.placeBelowWindow`) so it can't cover the send button.
- **Hotkey Modes**: `isChatInputMode` (panel "Mode": Voice / Chat; opening the chat switches to Chat, closing it with the X or picking Voice slides it away and switches to Voice). Voice: hold to talk (press/release, drawing while held). Chat: a press stops whatever is in progress, then opens/focuses the chat, or minimizes it if it is already open and focused (`toggleChatPanelFromHotkey`).
- **Visual Explanations & Live Notes**: Claude appends `[SHOW:what to explain]` (diagram) or `[NOTES:what to cover]` (summary/notes) and keeps its own reply to a one-line intro. A second `claude -p` call (`visualExplanationSystemPrompt` / `liveNotesSystemPrompt`; notes also get the screenshots) streams JSON lines: a title, then steps of `{"t":"say"}` narration followed by that step's lines. `NarratedStepQueue` plays steps in lockstep — a step's lines appear while its sentence is spoken (`LocalTTSClient.speakTextAndWaitUntilFinished`). Narration follows the user's language; panel text is always English; no emoji. **Teaching style (core product principle):** be direct and exact by default (formulas, theorems, definitions, simple facts get no analogy); only for genuinely complex/abstract topics, or when the user asks to simplify, explain through one everyday analogy from the user's own life (Indian daily life for Hindi/Hinglish speakers), carried all the way through, real term after it lands. Enforced in the voice, diagram and notes prompts; diagrams show analogies with `like` captions (space reserved in the layout), notes with an `analogy` card. **Math mode** for math/physics/graphs: exact board coordinates on an 800×500 area — `polygon`, `square_on` (exact square on a segment, optional unit `grid`), `line`, `path`, `angle`, `point`, `ring`, `pie`, `label`, `formula`, `latex` (KaTeX as an HTML overlay kept over an invisible placeholder rect by `positionFormulaOverlays`; WebKit paints KaTeX's positioned spans inside a foreignObject without the viewBox transform); plus graphs in math coordinates inside the latest `axes` (grid, ticks): `plot` and `area` (expressions in x), `parametric` (x(t), y(t)), `tangent` (numeric derivative), `mark`, `vector`, and `numberline`. Expressions are compiled by a small recursive-descent parser in the page (`compileExpression`: + − × ÷ ^, implicit multiplication, pi/e, trig/log/sqrt/abs/…; never `eval`). Claude must never compute curve points itself. Math mode is an infinite canvas too (Claude is told to spread out, give second figures their own axes beside or below, and leave latex/formula unplaced so they go under the drawing). Free labels on the board avoid each other automatically (`moveLabelToFreeSpot` spirals to the nearest spot clear of placed labels, shifting x/y since CSS transforms would be overridden by the appear animation). `pulse` runs 3 cycles, not forever, and the camera stops updating the viewBox once settled (endless sub-pixel updates re-rendered glow filters every frame and looked like blinking). Plot labels go in a stacked legend; `highlight` on math shapes glows instead of drawing an ellipse. Math shapes take highlight/pulse/tick/cross by id (position on an outer group, animations on an inner group so CSS transforms don't clobber position). **Clicky-style look and live drawing:** cream grid paper (faint 17-unit cells that pan and zoom with the camera, `moveGridWithCamera`), a page-drawn warm title bar with the lowercase `topic` (traffic lights show on hover; a `WindowDragStripView` keeps it draggable), Patrick Hand marker font (heading faux-bolded with a same-color stroke plus letter-spacing; kept because its looped l/t match the reference), flat pastel `PALETTE` fills with one clean stroke (`bluestrong` for key parts of technical drawings) (rough.js defaults: `disableMultiStroke`, low roughness), thin dark chevron arrows. A shared pen engine (`penAndScratchSoundScript`, a generator advanced per frame) reveals every new element in order: strokes trace via dash offset (duration by length), fills fade in after their outline, text writes left to right via clip-path; a gold triangle pen follows the drawing head (and fades once idle) and a WebAudio band-passed-noise scratch plays while drawing (`mediaTypesRequiringUserActionForPlayback = []`). `hb.stopDrawing()` (`VisualExplanationPanelManager.stopDrawing()`, called on the hotkey and in `close()`) reveals everything at once and cuts the sound; the sound also stops on `visibilitychange`. Diagram shapes glide on the pen's clock (`penFrameCallbacks`), not CSS transitions. Notes scroll to follow the pen (`onPenLeafStart`), and the writing head uses the text's real extent, not the block width. The pen shape (`penTriangleSVGPath`) and scratch sound (`pencilScratchSoundScript`, defines `scratchSound`) are static on `VisualExplanationPanelManager` and Swift substitutes them into the 3D page as well, so both pens look and sound the same. Relayout-redrawn arrows/groups are marked `data-pen="done"` so they are not retraced. Heading (with optional gray `sub`) sits at the left edge of the fit frame and, with captions, is counter-scaled by the zoom so it stays one size on screen; free labels keep a 15pt minimum on screen (`applyMinimumLabelSize`). The camera fits the drawing, zooming in up to `MAXIMUM_ZOOM_IN` to fill the width and centering it horizontally. Axes without ticks get default number ticks; area outlines repel later labels. Math mode adds `label` `pill` and `path` `smooth:false`. Panel calls run with `--effort low` so the first line streams in ~2s. The full streamed script is printed to the log for debugging. **Diagrams** use auto-layout: Claude declares `group`/`box`/`circle`/`icon`/`note`/`bars`/`arrow` with no coordinates and dagre lays out the graph after every addition (existing shapes glide; column gap compensates for dagre's cluster rank multiplier; arrow labels sit above the line, step badges opposite). Also `step`, `flow`, `highlight`, `cross`, `tick`, `shake`, `pulse`, `text`, `layout` (LR/TB). **Rows mode** (`row`, `caption`, `timeline`) is a left-aligned flow: boxes in a row share one height and a run of boxes one width, step badges sit in the left margin, every arrow has one length and the last ends at a board-wide result column that only grows (earlier results slide right); `timeline` draws evenly spaced dated dots on one line. In math mode `force` draws thick force arrows (`pair` for twin air streams, `labelColor`, label near the tip) and thick `path` strokes get round caps; the side-view prompt ships a normalized reference jet outline. Edge labels avoid shapes, group borders and arrow lines; arrows stop outside circles and highlight rings. Infinite canvas camera (eases to fit, scroll/drag pan, pinch zoom, double-click fit, refits on resize). **Notes** render `title`, `heading`, `bullet` (==highlight==), `remember`, `todo`, `quote`, `code` (Prism), `table`, `chart` (rough.js bar/line); all model text is inserted as text nodes. `[CLOSE_DRAWING]` hides the panel; asking to save notes uses osascript into Apple Notes. Pressing the hotkey cancels `currentVisualTask`. Locked-down WKWebView (CSP blocks network, navigation refused, non-persistent storage, commands passed as JSON data).
- **3D Models**: Claude appends `[MODEL3D:what to show:x,y:screenN]` for physical things (machines, hardware, vehicles, anatomy). A second `claude -p` call (`model3DSystemPrompt`, screenshots included, told which screenshot and its pixel size, `--effort low`) streams JSON lines played in lockstep via `NarratedStepQueue`. Claude works in real units (mm/m) from its knowledge of the object and starts with an `anchor` line: the object's box in screenshot pixels plus yaw/pitch/roll read off the screenshot, `place` (over/beside/left/right/above/below; side placements are capped at the photo's size), `scale`, `avoid` (page-text boxes label rows move clear of), `backdrop` (light/dark: outline and leader colors) and `shadow`. Commands: `part` (box with small default radius/`chamfer`, cylinder, cone, tube, sphere, torus, capsule, `extrude` with exact-size `bevel`/`round`/`holes` (rounded by `holeRound`)/`circles`/`shell`, `loft` cross-section bodies with `shell` (inner skin vertex-tinted dark for cutaways) and per-section `chine` (stealth nose), lathe, `ribbon`, `cable`; `sit` seats a part on another's top; `from` slides it in), `group`, `array`, helpers `pins`, `smd` (seeded scatter of small board parts in a footprint) and `port` (real-size connector library: usb-a/a2/usb3-2/usb-c/hdmi/hdmi-micro/rj45/ffc/microsd/audio), `arrow` (3D shaft+cone flow/force arrows that grow along their path, kept out of the fit), `move`, `explode`, `cutaway` (hatched stencil caps, dark inside), `label`, `highlight`, `focus`, `spin`, `fade`, `camera` (eases ~1s). `Model3DOverlay.swift` covers the whole target display with a transparent borderless non-activating panel and calls `hb.configure(screenshot size, focus point)` once the page loads; the page fits the model into the anchor rectangle (analytic fit plus a per-frame feedback correction of scale and center measured against the camera zoom, `setViewOffset`; no idle sway while anchored). It renders on demand (only while the view, tweens, spins, highlights or bounds change) and at 1.5x on very large displays; moving parts refresh bounds during their tween or a default box around the focus point. three.js r159 (`VisualToolkit/model3d.html` template; Swift substitutes in three.js, the Patrick Hand font, and the board's shared pen triangle and scratch sound), matte materials, 2px inverted-hull outlines (thinner on small parts, 1px for parts under 40px on screen), faint tight contact shadow, drag to orbit (double-click resets). Callout tags (Clicky colors, leader with opposite-color halo, ringed dot) anchor on a visible surface point found by raycasting from the camera against every part, so hidden parts are skipped (middle, then rims; stored in the mesh's frame so it follows moves), pick top/bottom automatically (left/right columns for the ends of long side views or on request), and rows hug the geometry under them (26px gap, 40px minimum leader). Row tags are placed in anchor-x order as balanced clusters (8px gaps) so leaders stay near vertical and never cross; when a leader would slant more than 40px, the label nearest the other row moves there once. The panel is click-through except over the model/labels (page posts hit regions, a timer toggles `ignoresMouseEvents`). Hotkey, `[CLOSE_DRAWING]`, Esc, or the hover close button close it; Esc and the close button also call `onUserClosedOverlay`, which cancels the narration. The local Esc monitor only swallows Esc aimed at the overlay.
- **Orb**: `OrbWindow.swift` hosts `VisualToolkit/orb.html` in a transparent (size from the panel's Orb → Size: Small 64 / Medium 88, the default / Large 116pt, `OrbSizeOption`, UserDefaults `orbSize`, applied live around the orb's centre) borderless non-activating `.screenSaver`-level panel (all Spaces), shown and hidden with the overlay (`OverlayWindowManager.orbWindowManager`). The page draws the bundled `orb.riv` with Rive's web runtime (`rive.js`, `@rive-app/canvas-single` 2.44.2, wasm inlined; Swift substitutes in the runtime and the .riv as base64). State machine `default`: booleans `speaking`/`asleep`/`thinking`/`listening`/`hover` (all false = idle) via `hb.setOrbState(name)`, number `color` 0-9 via `hb.setOrbColor(n)` (higher values look like 9). CSP adds `'wasm-unsafe-eval'` (required, or WebKit refuses the inlined wasm). `CompanionManager.bindOrbVisualState` maps listening (.listening), thinking (.processing and .responding: waiting for the first sentence, text-only typed replies, on-screen actions), speaking (only `isSpeakingAloud`, i.e. while audio plays; narrated whiteboard/3D steps speak through the same TTS), asleep (before onboarding or 5 minutes idle), idle otherwise. orb.riv's own asleep animation shrinks the orb to nothing and is slow to come back, so asleep is shown as the idle orb at 45% opacity. Hover (only over a resting orb) shows the riv's hover state and wakes it. A transparent view over the web view takes all mouse input: drag moves it (anywhere below the menu bar, Dock row included, `areaOrbMayUse`; origin saved in UserDefaults `orbWindowOriginX`/`orbWindowOriginY`; default in the Dock's row at the right edge of the main screen, centred on the Dock's height), a click follows the hotkey mode (`handleOrbClicked`: chat mode opens the chat, voice mode is tap to talk), pointing-hand cursor set by hand (non-key window). It fades out and turns click-through while bhai is resting, the system pointer is hidden (`SystemPointerVisibility`) and the frontmost app has a display-sized window (`frontmostAppHasFullScreenWindow`, via `CGWindowListCopyWindowInfo`); the fullscreen check stops it fading whenever macOS hides the pointer for typing. It reloads its page if the web content process dies. Excluded from screenshots like every own-app window. Color picked in the panel (Orb → "Color" swatches, UserDefaults `selectedOrbColor`, default 8). The logo (app icon and menu bar glyph) is the orb sending out a pointer: a glowing cyan-to-violet orb with a blue rounded arrow on a dark squircle, the arrow drawn larger for the 16-64px icons; the app icon is rendered once by a small CoreGraphics script (not kept in the repo), the menu bar glyph is drawn in code (`makeMenuBarIcon`).
- **Speaking Indicator**: `CompanionManager.isSpeakingAloud` drives `NotchSpeakingIndicatorView` in the overlay — a black pill hugging the notch (sized from `NSScreen.auxiliaryTopLeftArea`/`auxiliaryTopRightArea`) with a blue orb and voice bars; hangs from top center on displays without a notch.
- **Dependencies (SPM)**: `FluidAudio` (FluidInference/FluidAudio, 0.17.x), `WhisperKit` (argmaxinc/WhisperKit → `argmax-oss-swift`, 1.1.x).
- **Screen Capture**: ScreenCaptureKit (macOS 14.2+), multi-monitor support
- **Voice Input**: Push-to-talk via `AVAudioEngine`. System-wide keyboard shortcut via listen-only CGEvent tap.
- **Element Pointing**: Claude embeds `[POINT:x,y:label:screenN]` tags in responses. The overlay parses these, maps coordinates to the correct monitor, and launches the blue pointer (`BuddyPointerView`: soft rounded arrow, #3380FF to #2563EB gradient, white outline, glow) from the orb's center along a bezier arc to the target; after the label bubble it flies back and shrinks into the orb. Only the screen holding the target animates it; when the orb is on another display the pointer flies in from (and back off) that edge. The whiteboard/3D pen (`buddyDrawingPenScreenLocation`) launches it the same way; it follows the drawing head and returns after the pen has rested 1.2s. No pointer is on screen at rest.
- **Screen Circles**: Claude can also append `[CIRCLE:x,y,width,height:label:screenN]` (center + size, same coordinate space as POINT) to circle the exact on-screen text it is talking about. `parseCircleTags` strips them before POINT parsing (shares POINT's label/screen pattern and `globalAppKitLocation` mapping); the overlay traces each as a thin gold hand-drawn ellipse (`HandDrawnEllipseShape`: wobbly radius, ~1.1 turns so it overshoots, pill-like when wide) with `trim`, ~1.2s apart, kept until speech ends, then faded over 0.6s; cleared on hotkey press. **User drawing**: while the hotkey is held, `OverlayWindow` (a non-activating `NSPanel`) stops ignoring mouse events and its `sendEvent` turns drags into gold freehand strokes (`userDrawnStrokes`); click-through returns on release. Each stroke's bounding box is mapped back to screenN + screenshot pixels (`CompanionScreenCapture.screenshotPixelRect`) and added to the prompt, plus a native-resolution crop (`captureRegionAsJPEG`) as an extra image. A drawing with no speech is sent as "What is this?". Strokes fade with Claude's circles when the reply ends.
- **Concurrency**: `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`, async/await throughout

### Key Architecture Decisions

**claude binary lookup**: GUI apps launch with a minimal PATH, so `ClaudeCLI` checks `~/.local/bin`, `~/.claude/local`, `/opt/homebrew/bin`, `/usr/local/bin`, then falls back to `zsh -ilc 'command -v claude'`.

**Conversation history**: stream-json input takes one user message per run, so the last 20 exchanges (agent rounds included, with action summaries) are folded into the prompt text rather than sent as separate turns.

**Menu Bar Panel Pattern**: The companion panel uses `NSStatusItem` for the menu bar icon and a custom borderless `NSPanel` for the floating control panel. This gives full control over appearance (dark, rounded corners, custom shadow) and avoids the standard macOS menu/popover chrome. The panel is non-activating so it doesn't steal focus. A global event monitor auto-dismisses it on outside clicks.

**Cursor Overlay**: One full-screen transparent `NSPanel` per screen hosts the pointer flights, onboarding bubbles (placed next to the orb), gold circles, user strokes, and the notch pill via SwiftUI through `NSHostingView`. It's non-activating, joins all Spaces, and never steals focus. Listening/thinking feedback lives in the orb's animation, not next to the mouse.

**Global Push-To-Talk Shortcut**: Background push-to-talk uses a listen-only `CGEvent` tap instead of an AppKit global monitor so modifier-based shortcuts like `ctrl + option` are detected more reliably while the app is running in the background.

**Onboarding**: Start → welcome text above the orb → Claude picks something on screen and the pointer flies out of the orb to it → "press control + option" prompt streams in above the orb.

## Build & Run

```bash
cd macos

# One time per machine: create the local signing certificate
./scripts/create-signing-cert.sh

# Build, sign with the local "hellobhai Local Signing" cert, and relaunch.
# Logs: build/hellobhai.log
./scripts/build-and-run.sh

# Compile check only (unsigned, separate DerivedData, reuses resolved packages):
xcodebuild -project leanring-buddy.xcodeproj -scheme leanring-buddy -derivedDataPath /tmp/hb-dd \
  -clonedSourcePackagesDirPath build/DerivedData/SourcePackages CODE_SIGNING_ALLOWED=NO ENABLE_DEBUG_DYLIB=NO build

# Known non-blocking warnings: Swift 6 concurrency warnings,
# deprecated onChange warning in OverlayWindow.swift. Do NOT attempt to fix these.
```

**Signing and permissions**: macOS ties TCC grants (mic, accessibility, screen recording) to the code signature. `build-and-run.sh` always signs with the same self-signed "hellobhai Local Signing" certificate (in the login keychain), so grants survive rebuilds. Ad-hoc or differently-signed builds lose them. It builds with `ENABLE_DEBUG_DYLIB=NO` because re-signing doesn't cover Xcode's separate `hellobhai.debug.dylib` and dyld refuses to load it. On a new machine, run `./scripts/create-signing-cert.sh` once first (or set a real team in Xcode).

## Swift Conventions

Shared naming and clarity rules are in ../CLAUDE.md.

- Use SwiftUI for all UI unless a feature is only supported in AppKit (e.g., `NSPanel` for floating windows)
- All UI state updates must be on `@MainActor`
- Use async/await for all asynchronous operations
- Comments should explain "why" not just "what", especially for non-obvious AppKit bridging
- AppKit `NSPanel`/`NSWindow` bridged into SwiftUI via `NSHostingView`
- All buttons must show a pointer cursor on hover
- For any interactive element, explicitly think through its hover behavior (cursor, visual feedback, and whether hover should communicate clickability)

## Do NOT

- Do not add features, refactor code, or make "improvements" beyond what was asked
- Do not add docstrings, comments, or type annotations to code you did not change
- Do not try to fix the known non-blocking warnings (Swift 6 concurrency, deprecated onChange)
- Do not rename the project directory or scheme (the "leanring" typo is legacy; renaming breaks the Xcode project)
- Build with `scripts/build-and-run.sh`, not ad-hoc signed `xcodebuild` — other signatures invalidate TCC permissions

When something here changes (new or deleted files, architecture, build steps, line counts drifting by more than 50), update this file in the same change.
