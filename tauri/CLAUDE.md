# hellobhai for Windows (Tauri) - Agent Instructions

Shared naming and clarity rules are in ../CLAUDE.md. Layout, regenerating `generated/`, checking from a Mac and building on Windows are in `README.md`. Nothing here has run on Windows yet; verification is `cargo check` (host), `scripts/check-windows-target.sh` and `cargo test`. The assistant is called "bhai" in all UI text; "hellobhai" is only the app name.

## Architecture

- **App type**: tray-only Tauri 2 app (Rust + WebView2), plain HTML/JS pages with no framework or bundler. Every window is created in Rust; `RunEvent::ExitRequested` is prevented so closing windows never quits. Single instance; registers launch at login on first launch like the Mac.
- **OS boundary**: only `src-tauri/src/platform/` calls OS APIs. `platform/windows/` and `platform/unsupported/` expose the same free functions (no traits); Linux later = add `platform/linux/` with the same file names and one `cfg` line in `platform/mod.rs`.
- **Brain** (`companion_brain.rs`, port of the Mac's `CompanionManager`): hotkey press cancels everything (aborts the response and visual tasks, which kills a running `claude` via `kill_on_drop`; stops speech; finishes and stops the board; closes the 3D window; hides the settings panel; emits `clear-annotations`), lets the overlays take mouse drags for user drawing and starts recording. Release stops recording, transcribes with Whisper, then `send_transcript` (or "What is this?" when the user only drew). Spoken and typed questions share `send_message` (`send_transcript` for voice, `send_typed_chat_message` for the chat). Agent loop of up to 8 rounds: screenshot every monitor -> `claude -p` with the voice prompt and the platform tool allowlist -> `response_tags::parse_reply` (Mac order: actions, CLOSE_DRAWING, SHOW, NOTES, MODEL3D, CIRCLE, POINT) -> point, speak (after the previous speech ends), circle, act (the buddy flies to each click target 1.2 s before clicking); stops on no actions or a repeated action list. Every round is appended to the last-20 history with an action summary. No lock is held across an await.
- **Typed chat and bhai modes** (`chat_panel.rs`, `chat_conversation.rs`, `ui/chat.*`, port of the Mac's `ChatPanel.swift`): a 380 px transparent, topmost, focusable card that slides in from the right or left edge of the monitor under the mouse (full work-area height, 12 px inset, side in settings `chatPanelSide`). Tauri can't animate frames, so a task steps position/size at ~60 Hz with the Mac curves (0.2, 0.9, 0.3, 1 / ease-in) and the page fades its own content. Minimize (chevron, Esc in the page, Alt+F4, or the chat hotkey) shrinks it to a 30x112 tab flush with the edge with an unread dot once reply text arrives. Every turn lands in the chat rows (`ChatConversation`); replies stream into a placeholder with only bhai's own tags hidden (`chat_display_text_for_partial_reply`, `[OPEN]` included); a drop guard finishes a request's rows even when it is aborted. Reply rules (`reply_routing`): spoken -> voice + text (`speaksVoiceReplies`, default) or text only (the chat opens without leaving voice mode); typed -> text or text + voice (`speaksChatReplies`); narrated board/3D always speak. bhai mode (`isChatInputMode`): Voice = hold to talk; Chat = a press stops everything, then opens the chat or minimizes it when open and focused; opening the chat switches to Chat, the X switches to Voice, chat mode shows the chat at launch. The chat remembers the window that had the keyboard (`platform::foreground_window_id`) and hands it back (`platform::bring_window_to_foreground`) on minimize and before computer actions, during which it is click-through. Mode/settings changes go to every window as `chat-settings-changed` (the orb hides in chat mode); `CompanionBrain::handle_orb_clicked` follows the mode.
- **Claude** (`claude_cli.rs`): the Mac's flags in the Mac's order, but `--system-prompt-file` (prompt files are written to `app_local_data_dir/prompts` on every launch) instead of `--system-prompt`, because of the Windows command-line limit. Runs from the temp dir, stdin written and stderr drained on their own tasks, `CREATE_NO_WINDOW`, and each child in its own kill-on-close job object whose guard (`platform::kill_process_tree_when_dropped`) is dropped with the request, so a cancel kills the whole tree (node.exe behind an npm `claude.cmd` too); whisper-server's guard lives for the app's lifetime. Voice turns add `platform::voice_turn_tool_arguments`; side calls use `--tools ""`, and board/notes/3D calls `--effort low`.
- **Claude's tools** (`platform/windows/claude_tools.rs`): voice turns get `--tools Read,Glob,Grep` (read-only, allowed), `--add-dir <home>` and the shared Start menu folder. No shell tool: a PowerShell allowlist can't be made tight (`Start-Process` runs any program, script blocks run anything). Opening apps/files/links is the `[OPEN:target]` action tag, checked by `computer_control::allowed_open_target` (allowed link schemes, `shell:AppsFolder\<id>`, notepad/calc/mspaint/explorer, non-executable files and folders under home, apps by Start menu .lnk name) and run with ShellExecuteW. `claude.exe` is found in `%USERPROFILE%\.local\bin`, WinGet Links, then `where.exe`.
- **Side calls**: `[SHOW]`/`[NOTES]`/`[MODEL3D]` start a second claude call whose JSON lines go `StreamedLineForwarder` -> `NarratedStepQueue` -> board or 3D window; the queue plays `{"t":"say"}` steps in lockstep with `SpeechPlayer::speak_text_and_wait_until_finished` while the script is still streaming (`tokio::join!`). Narrations (and notes as plain text) are appended to the last history entry. Esc or the 3D close button aborts the narration.
- **Voice input**: `push_to_talk.rs` turns a listen-only `WH_KEYBOARD_LL` hook (`platform/windows/keyboard_hook.rs`) into press/release/cancel/Escape. Default shortcut ctrl + win (ctrl + alt would fire on AltGr); a win shortcut sends VK 0xE8 so releasing Win doesn't open Start. A modifier-only chord counts only after 150 ms with no other key, and another key joining it later cancels the recording, so win+ctrl+left/right/d/f4/enter pass through. Tracked keys the OS reports as up (key-ups lost to the lock screen or UAC) are dropped on every event. Esc closes the 3D model only while the pointer is over it. `audio_capture.rs` records the default mic with cpal (mono, low-pass filtered then resampled to 16 kHz). whisper-server gets the app folder first on PATH for the app-local Visual C++ DLLs, and its client never uses the system proxy. `whisper_transcriber.rs` runs whisper.cpp's `whisper-server` (b5454, `ggml-large-v3-turbo-q5_0`) on a free localhost port; Urdu is re-run as Hindi. No speech-to-text fallback while it downloads: bhai says "my ears are still downloading".
- **Voice output**: `speech_player.rs` + `supertonic.rs` run Supertonic-3 (voice F2 by default, ten voices) over ONNX Runtime, loaded from the downloaded `onnxruntime.dll` by absolute path (System32 has an older copy). Sentences with Devanagari are spoken as Hindi. One sentence is synthesized while the previous one plays; the WinRT system voice (`platform/windows/system_voice.rs`) speaks until the model loads or if it fails.
- **Screen and hands**: GDI `BitBlt` capture of every monitor (cursor screen first, JPEG, long side 1280; Mac screen labels), `screen_mapping.rs` maps screenshot pixels to global physical pixels, `SendInput` for clicks, Unicode typing and key combos (`key_combo.rs`: cmd becomes ctrl, option becomes alt).
- **Windows and pages**: one transparent, topmost, click-through overlay per monitor (`ui/overlay.js`, a port of `OverlayWindow.swift`: buddy, bezier flight, bubble, waveform, spinner, speaking pill, gold circles, user drawing while the hotkey is held, hides when the real pointer is hidden). One reused board window that switches between `generated/board.html` and `generated/notes.html`; a monitor-sized transparent 3D window (`generated/model3d.html`) that is click-through outside the hit regions the page posts. The tray icon toggles the settings panel (`ui/settings.*`). Every window comes from `page_bridge::locked_down_window_builder` (`content_protected` keeps them out of screenshots, navigation limited to app pages, popups denied).
- **Prompts**: `generated/prompts/*.txt` are exported from the Mac app with Windows wording (`prompt-substitutions.json`) and compiled in with `include_str!`. Never edit them by hand.
- **Settings**: `app_config_dir/settings.json` (claude model alias, Supertonic voice, push-to-talk shortcut, onboarding done, bhai mode, reply rules, chat side); missing or corrupt means defaults. Models go to `%LOCALAPPDATA%\ai.hellobhai.desktop\Models`.

## Rust -> page events

Overlay-only (`page_bridge::emit_to_overlays`): `audio-level {level}`, `point-at {x, y, bubbleText}` (global physical pixels; bubble text is the click label or the onboarding comment, else null), `screen-circles {circles: [{x, y, width, height, appearDelaySeconds}]}`, `fade-annotations`, `clear-annotations` (also cancels a pointing flight), `onboarding-text {text, visible}` (the overlay types the text out), `pointer-state`, `pen-position`, `drawing-enabled`. Every window (the settings page listens too): `buddy-voice-state {state}`, `speaking-changed {isSpeaking}`, `voice-load-state-changed`, `chat-settings-changed {isChatInputMode, speaksVoiceReplies, speaksChatReplies, chatPanelSide}`. Chat window only: `chat-state {messages, isMinimized, hasUnreadReply, isShown, chatPanelSide, modelLabel, speaksChatReplies}`.
