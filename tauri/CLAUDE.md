# hellobhai for Windows and Linux (Tauri) - Agent Instructions

Shared naming and clarity rules are in ../CLAUDE.md. Layout, regenerating `generated/`, checking from a Mac and building on Windows/Linux are in `README.md`. Nothing here has run on Windows or Linux yet; verification is `cargo check` (host), `scripts/check-windows-target.sh`, `scripts/check-linux-target.sh` and `cargo test`. The assistant is called "bhai" in all UI text; "hellobhai" is only the app name. The Mac app (`../macos/`) is the source of truth for behaviour: every feature here should do what the Mac does.

## Architecture

- **App type**: tray-only Tauri 2 app (Rust + WebView2 on Windows, WebKitGTK on Linux), plain HTML/JS pages with no framework or bundler. Every window is created in Rust; `RunEvent::ExitRequested` is prevented so closing windows never quits. Single instance; registers launch at login on first launch like the Mac.
- **OS boundary**: only `src-tauri/src/platform/` calls OS APIs. `platform/windows/`, `platform/linux/` and `platform/unsupported/` expose the same free functions (no traits); a new platform function goes into all three. Linux (README "Linux"): X11 through x11-dl (dlopen: XTest input incl. spare-keycode Unicode typing, XInput2 raw keys for push-to-talk, XGetImage, XFixes pointer, EWMH focus/fullscreen), xdg-open/gtk-launch for `[OPEN]`, process groups + PDEATHSIG for children, espeak-ng fallback voice; Wayland runs through XWayland (`prepare_process_environment` in `main`) with the screenshot portal and `/dev/input` push-to-talk, and `platform_limitation_note` explains the rest. Runtime archives are per platform (`RuntimeDownload::archive_file_name`/`keep_archive_entry`; zip or `.tar.gz` via `downloads::extract_archive_entries`). Linux prompt wording: `platform/linux_prompt_wording.rs`.
- **Brain** (`companion_brain.rs`, port of the Mac's `CompanionManager`): hotkey press cancels everything (aborts the response and visual tasks, which kills a running `claude` via `kill_on_drop`; stops speech; finishes and stops the board; closes the 3D window; hides the settings panel; emits `clear-annotations`), lets the overlays take mouse drags for user drawing and starts recording. Release stops recording, transcribes with Whisper, then `send_transcript` (or "What is this?" when the user only drew). Spoken and typed questions share `send_message` (`send_transcript` for voice, `send_typed_chat_message` for the chat). Agent loop of up to 8 rounds: screenshot every monitor -> `claude -p` with the voice prompt and the platform tool allowlist -> `response_tags::parse_reply` (Mac order: actions, CLOSE_DRAWING, SHOW, NOTES, MODEL3D, CIRCLE, POINT) -> point, speak (after the previous speech ends), circle, act (the buddy flies to each click target 1.2 s before clicking); stops on no actions or a repeated action list. Every round is appended to the last-20 history with an action summary. No lock is held across an await.
- **Typed chat and bhai modes** (`chat_panel.rs`, `chat_conversation.rs`, `ui/chat.*`, port of the Mac's `ChatPanel.swift`): a 380 px transparent, topmost, focusable card that slides in from the right or left edge of the monitor under the mouse (full work-area height, 12 px inset, side in settings `chatPanelSide`). Tauri can't animate frames, so a task steps position/size at ~60 Hz with the Mac curves (0.2, 0.9, 0.3, 1 / ease-in) and the page fades its own content. Minimize (chevron, Esc in the page, Alt+F4, or the chat hotkey) shrinks it to a 30x112 tab flush with the edge with an unread dot once reply text arrives. Every turn lands in the chat rows (`ChatConversation`); replies stream into a placeholder with only bhai's own tags hidden (`chat_display_text_for_partial_reply`, `[OPEN]` included); a drop guard finishes a request's rows even when it is aborted. Reply rules (`reply_routing`): spoken -> voice + text (`speaksVoiceReplies`, default) or text only (the chat opens without leaving voice mode); typed -> text or text + voice (`speaksChatReplies`); narrated board/3D always speak. bhai mode (`isChatInputMode`): Voice = hold to talk; Chat = a press stops everything, then opens the chat or minimizes it when open and focused; opening the chat switches to Chat, the X switches to Voice, chat mode shows the chat at launch. The chat remembers the window that had the keyboard (`platform::foreground_window_id`) and hands it back (`platform::bring_window_to_foreground`) on minimize and before computer actions, during which it is click-through; bhai's own windows are never remembered, Wayland remembers nothing, and when there is nothing to hand back to or that fails the chat is hidden and re-shown (the Mac's order-out trick) and the window that got the keyboard meanwhile is activated. Mode changes from the X, the hotkey, or the settings page (`change_setting` -> `ChatPanel::apply_chat_input_mode`) also hide or show the orb (`OrbWindow::set_hidden_for_chat_mode`); while the chat is shown the orb is kept under it (`place_below_window`; `platform::raise_always_on_top_window` restacks, since re-setting always-on-top is a no-op). Orb and chat resize through `platform::set_fixed_size_window_size` (GTK won't shrink a non-resizable window below its first size).
- **Codex brain** (`brain_engine.rs`, `codex_cli.rs`, port of `CodexCLI.swift`): settings General -> Brain (Claude default / Codex). Every call goes through `brain_engine::ask_selected_brain`, which passes the `ClaudeRequest` to claude untouched or runs `codex exec --json --ephemeral --skip-git-repo-check --ignore-user-config --ignore-rules --sandbox read-only --cd <per-call temp folder> -c approval_policy="never" -c project_doc_max_bytes=0 -c web_search="disabled" -c model_instructions_file=<instructions.md: the prompt file, plus a no-file-tools note on voice turns> -c features.shell_tool=false -c features.apps=false -c features.plugins=false [-c model_reasoning_effort=…] --image=<jpgs> -- -` (prompt with image labels and folded history on stdin; TOML-escaped values; per-call folder removed on drop, also on cancel). Only completed `agent_message` items count and the last one is the answer; `turn.failed`/non-zero exit become errors with a `codex login` hint. Lookup: `platform::codex_executable_candidates()` (Windows: `.local\bin`, WinGet Links, `%APPDATA%\npm\codex.cmd`, `where.exe`; Linux: `~/.local/bin`, `/usr/local/bin`, `~/.npm-global/bin`, then PATH). Codex model is the CLI default; effort Default/Low/Medium/High, panels still force low.
- **Claude** (`claude_cli.rs`): the Mac's flags in the Mac's order, but `--system-prompt-file` (prompt files are written to `app_local_data_dir/prompts` on every launch) instead of `--system-prompt`, because of the Windows command-line limit. Runs from the temp dir, stdin written and stderr drained on their own tasks, `CREATE_NO_WINDOW`, and each child in its own kill-on-close job object whose guard (`platform::kill_process_tree_when_dropped`) is dropped with the request, so a cancel kills the whole tree (node.exe behind an npm `claude.cmd` too); whisper-server's guard lives for the app's lifetime. Voice turns add `platform::voice_turn_tool_arguments`; side calls use `--tools ""`, and board/notes/3D calls `--effort low`.
- **Claude's tools** (`platform/windows/claude_tools.rs`): voice turns get `--tools Read,Glob,Grep` (read-only, allowed), `--add-dir <home>` and the shared Start menu folder. No shell tool: a PowerShell allowlist can't be made tight (`Start-Process` runs any program, script blocks run anything). Opening apps/files/links is the `[OPEN:target]` action tag, checked by `computer_control::allowed_open_target` (allowed link schemes, Windows only: `shell:AppsFolder\<id>`, `ms-settings:`, notepad/calc/mspaint/explorer; non-executable files and folders under home, apps by Start menu .lnk name) and run with ShellExecuteW. `claude.exe` is found in `%USERPROFILE%\.local\bin`, WinGet Links, then `where.exe`. Linux (`platform/linux/claude_tools.rs`): the same read-only tools plus home and the app folders; `[OPEN]` runs `xdg-open`, or `gtk-launch` for apps found by `.desktop` file or display name (system, user, Flatpak, Snap); script/launcher/installer extensions and any file with an execute bit are refused; `claude`/`codex` are found in the usual Linux paths, then the login shell.
- **Side calls**: `[SHOW]`/`[NOTES]`/`[MODEL3D]` start a second claude call whose JSON lines go `StreamedLineForwarder` -> `NarratedStepQueue` -> board or 3D window; the queue plays `{"t":"say"}` steps in lockstep with `SpeechPlayer::speak_text_and_wait_until_finished` while the script is still streaming (`tokio::join!`). Narrations (and notes as plain text) are appended to the last history entry. Esc or the 3D close button aborts the narration.
- **Voice input**: `push_to_talk.rs` turns a listen-only `WH_KEYBOARD_LL` hook (`platform/windows/keyboard_hook.rs`) into press/release/cancel/Escape. Default shortcut ctrl + win (ctrl + alt would fire on AltGr); a win shortcut sends VK 0xE8 so releasing Win doesn't open Start. A modifier-only chord counts only after 150 ms with no other key, and another key joining it later cancels the recording, so win+ctrl+left/right/d/f4/enter pass through. Tracked keys the OS reports as up (key-ups lost to the lock screen or UAC) are dropped on every event. Esc closes the 3D model only while the pointer is over it. `audio_capture.rs` records the default mic with cpal (mono, low-pass filtered then resampled to 16 kHz). whisper-server gets the app folder first on PATH for the app-local Visual C++ DLLs, and its client never uses the system proxy. `whisper_transcriber.rs` runs whisper.cpp's `whisper-server` (b5454, `ggml-large-v3-turbo-q5_0`) on a free localhost port; Urdu is re-run as Hindi. No speech-to-text fallback while it downloads: bhai says "my ears are still downloading". Linux: XInput2 raw key events (listen-only, works while the window manager holds Super; the app's own XTest typing is ignored), or `/dev/input` on Wayland for users in the `input` group; Super is labelled `super` (`platform::SUPER_KEY_DISPLAY_NAME`) and needs no Start-menu workaround. whisper.cpp b5454 `whisper-bin-ubuntu-x64.tar.gz`.
- **Voice output**: `speech_player.rs` + `supertonic.rs` run Supertonic-3 (voice F2 by default, ten voices) over ONNX Runtime, loaded from the downloaded `onnxruntime.dll` by absolute path (System32 has an older copy). Sentences with Devanagari are spoken as Hindi. One sentence is synthesized while the previous one plays; the WinRT system voice (`platform/windows/system_voice.rs`) speaks until the model loads or if it fails. Linux: ONNX Runtime 1.31.1 `onnxruntime-linux-x64-1.31.1.tgz`; `espeak-ng` speaks until Supertonic loads.
- **Screen and hands**: GDI `BitBlt` capture of every monitor (cursor screen first, JPEG, long side 1280; Mac screen labels), `screen_mapping.rs` maps screenshot pixels to global physical pixels, `SendInput` for clicks, Unicode typing and key combos (`key_combo.rs`: cmd becomes ctrl, option becomes alt). Our own windows stay out of screenshots like on the Mac: Windows via `content_protected`; Linux can't exclude them (`platform::CAPTURE_EXCLUDES_OWN_WINDOWS = false`), so `screen_capture::hide_own_windows_the_capture_would_see` hides every visible non-overlay window and blanks the overlays (`hidden-for-capture`) for ~60 ms around each capture and region crop; the returned guard restores them on drop (also when the turn is cancelled mid-capture) and refocuses the one that had the keyboard. Deliberate hides go through `screen_capture::hide_window` so a capture never re-shows a window put away meanwhile. Linux typing checks keys at the active XKB layout group. Linux: XGetImage per monitor on X11, the screenshot portal on Wayland; XTest clicks and keys, characters missing from the layout typed by briefly remapping a spare keycode.
- **Windows and pages**: one transparent, topmost, click-through overlay per monitor (`ui/overlay.js`, a port of `OverlayWindow.swift`: the pointer launching from its home along a bezier arc, label bubble, pen following, onboarding bubbles, speaking pill on every monitor, gold circles, user drawing while the hotkey is held). Voice style (`settings.voiceBuddyStyle`): orb (default; the rounded gradient arrow launches small out of the orb's centre and shrinks back in, nothing on screen at rest, listening/thinking shown by the orb) or cursor (the classic 16 px blue triangle follows the mouse at +35, +25 on the mouse's monitor, waveform while listening, spinner while thinking, hides with the real pointer when idle, launches from and lands back beside the mouse). Chat mode ignores the style. Only the monitor holding a target animates; overlays report a pointer away from home (`overlay_pointer_away_changed`) so the cursor style's following pointer hides while another monitor's is out.
- **Orb** (`orb_window.rs`, port of `OrbWindow.swift`): `generated/orb.html` (the Mac page with Rive's runtime and `orb.riv` inlined by the exporter) in a transparent, topmost, non-focusable window, shown in voice mode with the orb style. `ui/orb-host-bridge.js` (initialization script) sends pointer events to `orb_pointer_*`/`orb_hover_changed`; Rust tells drag (3 logical px) from click and moves the window in physical pixels, clamped to the monitor minus a top taskbar (the bottom taskbar row is allowed). Default spot: the bottom taskbar's row at the right edge of the primary monitor, 20 px in, centred on the taskbar height (Mac: the Dock row); dragged spot saved as `orbWindowOrigin` (physical px), reused only while it touches a connected monitor. Size 48-160 logical px in 2 px steps (default 88) applied around the centre; colour 0-9 (`selectedOrbColor`, Aurora 8 default; names and swatches live in `ui/settings.js`) via `hb.setOrbColor`. State from `buddy-voice-state` + `speaking-changed` (Rust listeners): listening, thinking (processing/responding), speaking (only while audio plays), asleep (before onboarding or 5 idle minutes; idle at 45 % opacity), hover over a resting orb. A click in voice mode is tap to talk (sent into the hotkey channel). Every 250 ms: fades out and turns click-through while resting, the real pointer is hidden and the foreground window fills its monitor (`platform::is_foreground_window_full_screen`); every 2 s it re-asserts topmost (the taskbar can rise over it) and moves back onto a connected monitor. `OrbClickThroughWhileActing` (held by `perform_computer_actions`) makes it click-through during on-screen actions. Hidden in chat mode (`set_hidden_for_chat_mode`, which also re-homes the overlay pointer; read from settings at launch) and kept under a shown chat (`place_below_window`). Size, colour and style changes arrive from `change_setting` (`apply_orb_size`, `apply_orb_color`, `apply_voice_buddy_style`). Emits `buddy-home-changed` to the overlays. One reused board window that switches between `generated/board.html` and `generated/notes.html`; a monitor-sized transparent 3D window (`generated/model3d.html`) that is click-through outside the hit regions the page posts. The tray icon toggles the settings panel (`ui/settings.*`). Every window comes from `page_bridge::locked_down_window_builder` (`content_protected` keeps them out of screenshots, navigation limited to app pages, popups denied).
- **Prompts**: `generated/prompts/*.txt` are exported from the Mac app with Windows wording (`prompt-substitutions.json`); on Linux the prompt files get Linux wording when written (`platform/linux_prompt_wording.rs`, tests check every swap) and compiled in with `include_str!`. Never edit them by hand.
- **Settings** (`settings.rs`, `ui_commands.rs`): `app_config_dir/settings.json` with the Mac's settings and defaults: claude model alias, Supertonic voice, push-to-talk shortcut, onboarding done, `brainEngine`, `codexReasoningEffort`, `isChatInputMode` (bhai mode), `speaksVoiceReplies` (true), `speaksChatReplies` (false), `chatPanelSide` (right), `voiceBuddyStyle` (orb), `orbSideLength` (88, 48-160 in 2 px steps), `selectedOrbColor` (8 = Aurora), `orbWindowOrigin` (dragged spot); saved one write at a time through a temporary file and a rename; missing or corrupt means defaults. The page changes them with one command, `change_setting {name, value}` (checked in `apply_setting_change`), and every change is saved and emitted to every window as `settings-changed` (the full `SettingsSnapshot`), which the settings and chat pages follow; `change_setting` then applies the change live (voice, bhai mode, chat side, chat model label, orb style/size/colour). The chat's own buttons save through the same `save_and_announce_settings`. Models go to `%LOCALAPPDATA%\ai.hellobhai.desktop\Models` (Linux: `~/.local/share/ai.hellobhai.desktop/Models`).
- **Settings panel** (`ui/settings.*`, 340 px): the logo in the header, General (bhai mode, brain + Claude model or Codex effort + CLI found/not found, speech-to-text status, shortcut recorder, microphone, launch at login, replay onboarding) / Voice (voice + preview/stop, "Speaking with") / Chat (when you speak, when you type, chat side) / Buddy (voice style, orb size slider, colour dropdown dimmed in the cursor style) tabs; the last tab is kept in localStorage. A platform note (`platform::platform_limitation_note`, e.g. Linux on Wayland) shows above the tabs.
- **Shortcut recorder**: like `PanelShortcutRecorder`. `set_shortcut_recording true` makes the push-to-talk thread feed raw keys to `push_to_talk::ShortcutRecorder` instead of the tracker (no push-to-talk while recording; a win key-down injects the Start suppression key); hold two or more of ctrl/left alt/shift/win and let go -> saved (a built-in combination is stored as that option, else `customModifiers {ctrl, alt, shift, win}`; alt = LEFT alt so AltGr never triggers it), one key -> "Use 2+ keys", Esc or hiding the panel stops. Updates reach the page as `shortcut-recorder {state: holding|needsTwoOrMoreKeys|stopped, keyLabels}`. A reset button goes back to the default.
- **Logo**: `icons/` (32/64/128/256/512 PNG, `icon.ico` 16-256, `tray.png`) and `ui/logo.png` (settings header, chat header and reply rows) are cropped from the Mac AppIcon PNGs (the hand-tuned 16-64 px renders with the larger arrow for small sizes); the tray uses `tray.png` via `include_image!`.

## Rust -> page events

Overlay-only (`page_bridge::emit_to_overlays`): `audio-level {level}`, `point-at {x, y, bubbleText}` (global physical pixels; bubble text is the click label or the onboarding comment, else null), `screen-circles {circles: [{x, y, width, height, appearDelaySeconds}]}`, `fade-annotations`, `clear-annotations` (also cancels a pointing flight), `onboarding-text {text, visible}` (the overlay types the text out), `pointer-state`, `pen-position`, `drawing-enabled`, `buddy-home-changed {voiceBuddyStyle, isChatMode, orbFrame}` (also the `buddy_home_state` command at start), `pointer-away-monitors {monitorIndices}`, `hidden-for-capture {hidden}` (Linux). Every window (the settings page listens too): `buddy-voice-state {state}`, `speaking-changed {isSpeaking}`, `voice-load-state-changed`, `settings-changed` (`SettingsSnapshot`: every setting in camelCase plus `pushToTalkDisplayText`, `pushToTalkKeyCapsuleLabels`, `isDefaultPushToTalkShortcut`, `defaultPushToTalkShortcut`, `defaultPushToTalkDisplayText`, `launchAtLogin`), `shortcut-recorder`. Chat window only: `chat-state {messages, isMinimized, hasUnreadReply, isShown, chatPanelSide, modelLabel, speaksChatReplies}`.
